# Ikrima

Приложение для мастерской индивидуального пошива мужской исламской одежды — с. Шатой.

Клиент смотрит каталог готовых размеров, покупает вещь с оплатой при получении или отправляет
заявку на пошив с мерками, снятыми со своей одежды, и записывается на примерку. Швея ведёт заказы
и отмечает наличие размеров в своём кабинете — каталог у клиента обновляется сразу.

Собрано по прототипу из `design/Ikrima - прототип.dc.html`.

## Запуск

```bash
npm install
npm run dev
```

Откроется на `http://localhost:5173`. Сборка — `npm run build`, проверка типов — `npm run typecheck`.

## Кабинет швеи закрыт кодом

В первый раз кабинет просит придумать код из четырёх цифр и повторить его. Дальше кабинет
открывается только по этому коду — включая прямую ссылку на конкретный заказ. Код хранится
хэшем (SHA-256), сам код нигде не записан. «Выйти» в конце кабинета закрывает его сразу;
кроме того, он закрывается сам, когда браузер закрывают. Сменить код можно изнутри кабинета.

**Что этот код делает и чего не делает.** Он не пускает в кабинет клиента, который нажал
«Кабинет швеи» на экране мастера или подставил адрес вручную. Настоящей защитой он не является:
приложение целиком работает в браузере, поэтому хэш видно в инструментах разработчика, а четыре
цифры перебираются быстро. Настоящий вход появится вместе с сервером — см. «Что дальше».
Если код забыт, восстановить его негде: придётся очистить данные сайта в браузере, вместе с
заказами.

## Где лежат данные

Сейчас — в браузере (`localStorage`), поэтому приложение работает без интернета и без сервера,
а данные сохраняются между запусками на этом устройстве. Это осознанный первый шаг: каталог у
каждого клиента свой, общего склада заказов пока нет.

Весь доступ к данным идёт через один интерфейс — `IkrimaRepository` в `src/data/repository.ts`.
Экраны о хранилище ничего не знают, поэтому переход на сервер их не затрагивает:

1. Поднимите сервер с базой и реализуйте эндпоинты, описанные в `src/data/http.ts`:

   ```
   GET    /data          → все данные магазина
   PUT    /stock         ← { model, size, available }
   POST   /orders        ← новый заказ
   PATCH  /orders/:id    ← изменения заказа
   POST   /slots/book    ← { label, orderId? }
   PUT    /settings      ← { lang, priceMode, tailorPinHash }
   ```

   Точные типы — в `src/types.ts` (`IkrimaData`). Когда появится сервер, код швеи должен
   проверяться на нём, а не отдаваться клиенту хэшем: этот эндпоинт — временная форма.

2. Задайте `VITE_API_URL` (см. `.env.example`) — и `createRepository()` сам переключится
   с браузера на сервер. Менять экраны не нужно.

Черновик заявки и корзина хранятся отдельно (`src/store/session.ts`): они принадлежат
посетителю, а не магазину, и на сервер уезжать не должны.

## Публикация на GitHub Pages

В репозитории лежит `.github/workflows/deploy.yml`. После первого пуша в `main`:

1. Settings → Pages → Source → **GitHub Actions**.
2. Дальше каждый пуш в `main` пересобирает и публикует сайт сам.

`base: ''` в `vite.config.ts` делает пути к файлам относительными, поэтому сборка одинаково
работает и на `user.github.io/ikrima/`, и на своём домене.

## Чем реализация отличается от прототипа

Прототип рисовали, а не собирали, поэтому несколько мест доведены до рабочего состояния:

- **Нижние панели.** В прототипе кнопки «В корзину», «Отправить заявку» и другие стояли
  `position:absolute` поверх контента и оказывались под таббаром. Здесь экран — колонка:
  шапка, прокручиваемое тело, панель действий, таббар. Ничего не перекрывается.
- **Отступ сверху.** Прототип резервировал ~58px под нарисованную строку состояния iOS.
  В браузере её рисует сама система, поэтому используется безопасная зона устройства.
- **Заказы создаются по-настоящему.** Прототип показывал «Заявка №144» и очищал корзину,
  ничего не сохраняя. Теперь и заявка на пошив, и покупка готовой вещи создают заказ, который
  виден клиенту в «Моих заказах» и швее в кабинете.
- **Готовая вещь идёт своими этапами** — «заказ принят · сборка · отправка · получен» вместо
  «мерки · раскрой · пошив · примерка · выдача». Шкала этапов в дизайне управляется данными,
  так что выглядит она точно так же.
- **Поиск работает.** В прототипе это была надпись, здесь — поле, которое фильтрует каталог.
- **Фото загружаются.** Пунктирные рамки стали выбором файла: снимок уменьшается до 720px,
  чтобы поместиться в хранилище браузера, и виден швее в кабинете.
- **WhatsApp и телефон** — настоящие ссылки на `+7 938 018-25-43`.
- **Режим цен** («точные / от / скрыть») был переключателем для дизайнера — теперь он в кабинете
  швеи, рядом с наличием размеров.
- **Клики стали кнопками.** Каждый `onClick` на `<div>` — настоящая кнопка: работает с клавиатуры
  и читается программой экранного доступа.
- **Кабинет закрыт кодом.** В прототипе он открывался по ссылке с экрана мастера. В опубликованном
  приложении так нельзя, поэтому перед ним появился экран с кодом.
